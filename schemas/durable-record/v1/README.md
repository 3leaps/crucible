# Durable record schema family v1

**Proposed / experimental.** Capability: `contract: durable-record/v1`.
Resolve through a trusted, pinned `contract.json`. The normative
[standard](../../../../docs/standards/durable-record-v1-contract.md) and
[ADR-0019](../../../../docs/decisions/ADR-0019-durable-record-tombstoning.md)
define retained-record restrictions and the v1 boundary.

| Artifact                         | Responsibility                                                             |
| -------------------------------- | -------------------------------------------------------------------------- |
| `stratum-profile.schema.json`    | Discovery, mandatory tombstoning and positive shared key window            |
| `record.schema.json`             | Record envelope `v: 1` (v0 plus optional `produced_at`) and revision digest |
| `journal-entry.schema.json`      | v1 content and protection journal entries                                  |
| `write-receipt.schema.json`      | Content receipts and reconciliation for either accepted operation family   |
| `protection-request.schema.json` | Exact target, scoped hold or targeted restore, evidence and attribution    |
| `protection-receipt.schema.json` | Accepted protection receipt or closed refusal outcome                      |
| `export-request.schema.json`     | Logical selection plus trusted current protection inputs and body bytes    |
| `export-result.schema.json`      | Decision at a cut; not a durable authorization token                       |
| `examples/`                      | Wire instances; filename prefix identifies the schema                      |
| `vectors/`                       | Ordered operations with authored expected receipts and final logical state |
| `rejects/schema/`                | One-field shape rejects with passing baselines                             |

Run `python3 scripts/test-durable-record-v1-controls.py`, also included in
`make check`. Vectors specify `window_ms`, an initial journal, ordered `steps`,
and `expected`. A step submits a protection request at a supplied store time,
adds a content journal entry, submits a keyed retirement, evaluates a logical
use request, or reconciles a key. Expected receipts are committed values, not generated by the interpreter.
A semantic failure is represented as `expected.refusal`.

The checker requires the v1 record schema to equal the v0 record schema after
changing `v` from `0` to `1` and adding only `produced_at` (and the instant
definition it references), and verifies shared schema definitions,
validates instances, interprets transitions and runs deliberate source mutations
against golden witnesses. Each mutation must yield acceptance or an exact named
alternative. The refusal table, emitted local reasons and witnessed reasons
must agree; schema/semantic fixture membership is separately inventoried.
It reuses v0 helpers and claims no independent decoder
or production store qualification. Authorization, physical propagation,
crash/restart, migrations and release races require adopter tests.
