# Durable record v1 fixture inventory

Schema pairs carry `schema`, `baseline` and `reject` and differ in one field.
Vectors declare exact expected outcomes. `invalid_journal_entries` identifies
zero-based positions deliberately failing shape validation; the same cases
also prove the semantic version and operation-type guards.
`invalid_receipt_steps` similarly identifies version-rejected receipt steps,
and `invalid_request_steps` identifies schema-rejected protection requests also
refused semantically. A `retire` step is a logical keyed-retirement request
`{stream, record_id, reason, idempotency_key}`; its receipt is a write receipt.
`invalid_use_steps` identifies schema-rejected purposes also refused semantically.
A continuation vector carries `source_journal`, the source journal the
enforcing store observes; a `source_entry` step appends to it, as a source
change outside the destination stream. `ancestors` lists the further source
journals the store observes when the source is itself a continuation, nearest
first; an `ancestor_entry` step appends to the named one.
A case may carry `profile`, the stratum profile of the store. When it names a
`body_removal_stream`, the case's `journal` is that stream. A `body_state` step
`{body, present}` returns the reader state of that body at the current cut.
`present` is a trusted observation: `true` is bytes verified against digest and
length, `false` is observed absence. An unknown or failed observation has no
step form: a malformed observation is refused as `body_observation`, and
`invalid_body_state_steps` names the steps that also fail the
`body-state-request` schema.
