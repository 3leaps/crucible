# Release v0.2.11

**Date:** 2026-11-13

**Adds the proposed, experimental `filesystem-access/v0` contract for portable access relative to a held directory object.**

## Highlights

- The [filesystem access standard](../standards/filesystem-access.md) defines
  root-relative names, trusted root acquisition, `containment/v0` and
  `no-links/v0`, bounded reads/listings, exclusive creation, and held-handle
  identity. It distinguishes physical link resolution, mount boundaries,
  reference lifetimes, and per-operation observation points.
- The [schema bundle](../../schemas/filesystem-access/v0/README.md) includes
  operation-specific requests/results, capability reports, admitted and
  observed names, and 62 declarative recipe cases.
- The [repository controls](../../scripts/test-filesystem-access-controls.py)
  exercise schema shapes, logical outcomes, mutation witnesses, and bounded
  native primitive availability. [ADR-0020](../decisions/ADR-0020-filesystem-access-contract.md)
  records the proposed contract boundary.

## Adoption notes

Pin an exact release or commit when adopting this experimental v0 contract.
Validate each runtime cell for its OS, filesystem, backend, operation, profile,
observation point and adversary level. Unsupported requested guarantees require
refusal without fallback.

Schema validity, logical corpus agreement and primitive availability are separate
from production resolver qualification. This release does not qualify concurrent
replacement resistance, Windows reparse handling, mount-boundary enforcement,
or a consumer implementation.

## What a release carries

A Crucible release is a GPG-signed annotated Git tag. It publishes no assets,
so there are no `SHA256SUMS` or `SHA512SUMS` files to verify. See
[release security](../security/README.md).
