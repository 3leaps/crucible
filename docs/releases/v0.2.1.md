# Release v0.2.1

**This repository's release tooling adopts PDR-0008, and PDR-0010 is
proposed.**

This is a patch release. It adds no contract family and changes no schema. It
changes how this repository's releases are verified. This release is the first
tag made under the adopted ceremony; the record's acceptance is recorded once
the tag verifies.

## Highlights

### Release public identity adopted (PDR-0008)

- **One checker.** The release fingerprint anchors are derived and verified by
  decernor 0.1.8 or newer. Tag verification reads every pin from the tagged
  commit and checks it with that tool; the repository carries no second
  parser.
- **Anchors.** `keys/expected-fingerprints.ndjson` joins
  `keys/expected-fingerprints.txt`. Both are derived twice and compared, never
  typed. The text anchors are unchanged byte for byte.
- **Explicit inputs.** Every tag step takes the tag from
  `THREELEAPS_CRUCIBLE_RELEASE_TAG`, and every step that reads a pin takes the
  checker from `THREELEAPS_CRUCIBLE_DECERNOR_BIN`: an absolute path to a
  regular, executable, non-symlink file. The tag is never derived from
  `VERSION` or `git describe`, and there is no `PATH` fallback.
- **CI.** The release workflow's read-only signature job downloads decernor by
  the digest pinned in `config/release/decernor-ci-sha256.txt`. A new
  `release-identity` check job runs the end-to-end tag controls against an
  ephemeral signing key.
- **Third-party key.** Bootstrap verifies goneat against the committed
  `docs/security/fulmenhq-goneat-minisign.pub`, never a key fetched from the
  goneat release.
- **Verifier guide.** `docs/security/README.md` states what a release carries
  and how to check it.

### Verified immutable release publication (PDR-0010, proposed)

A process decision for verifying a release's staged assets before immutable
publication: a committed release definition that resolves to an exact asset set
(zero for a tag-only release), a pre-publication verification record checked
again after publication, distinct reported outcomes, and immutability enabled
for a repository only once its ceremony makes every asset change while the
release is a draft. PDR-0004 carries a proposed-successor notice and still
governs this repository's publication. Filing PDR-0010 changes no workflow.

### CI baseline

`docs/operations/ci-baseline.md` now pins images by digest, actions by commit
and tools by version and digest. It adds gotchas for `grep -q` under
`pipefail`, Windows runners and images missing a tool, and a supply-chain
section.

## What a release carries

A crucible release is a GPG-signed annotated Git tag. It publishes no assets,
so there are no `SHA256SUMS` or `SHA512SUMS` files to verify. See
[`docs/security/README.md`](../security/README.md).

## Upgrade notes

- **For verifiers: the minisign pin is renamed.**
  `docs/security/release-minisign.pub` is now
  `docs/security/crucible-minisign.pub`. The key is unchanged; only the file
  name moved. Tags up to and including v0.2.0 carry the old name and verify
  with the `scripts/verify-pinned-tag.sh` from their own commit.
- **For anyone running the release scripts:** set
  `THREELEAPS_CRUCIBLE_RELEASE_TAG` and, for steps that read pins,
  `THREELEAPS_CRUCIBLE_DECERNOR_BIN`. `RELEASE_TAG`, `DECERNOR_BIN`,
  `THREELEAPS_CRUCIBLE_REQUIRE_TAG` and the unprefixed `CRUCIBLE_*` names are
  refused, even when empty. Unset them. See
  [`RELEASE_CHECKLIST.md`](../../RELEASE_CHECKLIST.md).
- No schema, contract or toolchain pin changes.
