# Release v0.1.26

**A contract-boundary cut: portable wait/poll and service-job families land
as `v0`, so a consumer can wait and submit against a shared message contract
instead of a provider-specific protocol.**

## Overview

v0.1.25 made the review methodology usable and checkable. v0.1.26 marks the
next tag boundary after two portable contracts landed: `contract:
agent-wait/v0` and `contract: service-job/v0`. Both ship as schemas, goldens,
and `make check` controls — message contracts, not daemons or clients.

The cut also folds what else landed on `main` after v0.1.25: the Composing a
Review Panel guide, an optional seat execution record on `review-journal/v0`,
the fierce-collaboration standard 0.5.0 → 0.6.0 disclosure move, the
close-out that made both new families fail closed, and a
`coverage-attestation/v0` harden. Docs-only version bump; no public API or
schema version break beyond the new contracts themselves.

## Highlights

### `contract: agent-wait/v0`

Portable wait/poll family for one aggregate waiter per consuming seat. Six
discriminated message kinds; start position is an explicit XOR
(`start_anchor` or `baseline_policy`); live match proposes
`proposed_next_anchor` and does not commit the cursor; poll `no_change` /
`logical_deadman` cannot validate as clean when required coverage is
degraded. Anchors are provider-opaque and distinct from source event IDs.
Transport-neutral: `delivery_ref` / `activation_ref` never imply agent
action.

Schemas, goldens, and schema/normative/set controls live under
`schemas/agent-wait/v0/`. The standard is
`docs/standards/agent-wait-contract.md`. Wired into `make check`.

### `contract: service-job/v0`

Portable service-job family: thirteen discriminated kinds from catalog list
through cancel and error. Catalogs are authorization-filtered; implicit
default is local-only; hosted submit requires an explicit backend and egress
authorization. Submit is digest-bound with RFC 8785 (JCS) — `jq -S` is not
JCS. Admission `accepted` is not started, completed, delivered, or
activated. Legal transitions; terminals never leave.

Schemas, goldens, JCS vectors, and controls live under
`schemas/service-job/v0/`. The standard is
`docs/standards/service-job-contract.md`. Wired into `make check`.

### Composing a Review Panel, and the record that makes a seat comparable

The composition companion to the fierce-collaboration standard and its
run-book, at `docs/guides/composing-a-review-panel.md`: the five-layer seat
model (identity × environment × harness+profile × mode × framing+capture),
three harness classes with composition rules and cross-class footguns, panel
diversity mechanics, the six-part framing block, a preflight checklist, and
copy-paste templates. Launch references stay symbolic — harness classes,
named profiles, and environment compositions, never invocation detail.

`review-journal/v0` gains an optional seat execution record: symbolic
`harness`, `profile_ref`, `environment_ref` (`inherited` admitted), `mode`,
and `capture` (no terminal-scrape form). Three reject/baseline pairs join
the negative-control battery. The standard moves 0.5.0 → 0.6.0: §3 records
the composition, §9.2 requires it for framing-comparison claims, and new
§9.3 makes the non-interactive verdict contract normative (one binary
disposition token, fail-closed; numbered severity-tagged findings; bounded
length).

### Close-out that made the new families checkable

The landed contracts include the P1 close-out that keeps them falsifiable:
a portable RFC3339 helper (contract date-time profile only; leap seconds
rejected rather than clamped), a JCS materializer on the RFC 8785 /
ECMAScript / I-JSON numeric domain, fail-closed checkers on missing or
unreadable targets, scoped idempotency with `unknown` admission blocking a
later scoped resubmit, restored lifecycle and digest identity, and
JobSpec-only execution selectors. The release-surface changelog grep now
consumes the whole stream so a legitimate Unreleased addition cannot look
like a missing version heading.

`coverage-attestation/v0` (still proposed) now requires a stable
machine-readable `code` on every gap and rejects negative observed or
expected volumes. Negative controls run under `make check`.

## Compatibility

`agent-wait/v0` and `service-job/v0` are new `v0` surfaces. Pin to a commit
if you need stability; both remain draft and may change without a repository
major bump.

`review-journal/v0` stays `v0`. The seat execution record is optional
(reserve-don't-force). Journals that omit it still validate; journals that
include an execution record without its harness token, with an empty
environment reference, or with a terminal-scrape capture form now fail.

`coverage-attestation/v0` is still proposed and was tightened in place:
attestations whose gaps lack `code`, or whose volumes are negative, will
not validate against v0.1.26 schemas.

No other contract family changes its capability token.
