# Release v0.2.9

**Specifies the `durable-record/v1` retention policy for retired-record body reclamation, designated `body-removal` stream recovery, and detached canonical `stream-seal` artifacts; adds the draft `identity-evidence/v0` `native-process-observation:v0` provider profile; and hardens the RFC 8785 JCS and RFC 3339 instant helper scripts.**

This release completes the `durable-record/v1` external-body lifecycle surfaces
for policy-bound reclamation of body bytes referenced only by retired records,
quarantined designated `body-removal` stream recovery via successor journals, and
detached verified stream seals across continuation chains. It also adds the
draft `native-process-observation:v0` provider profile under
`identity-evidence/v0` and hardens the repository's RFC 8785 canonical JSON and
RFC 3339 instant validation helpers.

## Highlights

### `durable-record/v1` retention policy for all-retired-record body reclamation

- **Eligibility rules and deterministic refusal precedence.** Updates
  [`docs/standards/durable-record-v1-contract.md`](../standards/durable-record-v1-contract.md)
  and adds
  [`schemas/durable-record/v1/removal-eligibility-request.schema.json`](../../schemas/durable-record/v1/removal-eligibility-request.schema.json)
  to define when a store may remove external body bytes `(digest, length)` that
  historical records have referenced once every referencing record across the
  store is retired. Enforces deterministic Precedence `1 -> 2 -> 2b -> 3 -> 4 -> 5`
  refusal ordering: designated-stream placement, request/journal wire and domain
  preflight, and target `incarnation` lifecycle transition eligibility (`1`,
  refusing `ingest`, `numeric_domain`, `shape`, `instant_spelling`,
  `body_removal_stream`, or `body_lifecycle`), store-wide stream coverage,
  `quarantined_designated_streams` predecessor-chain completeness, valid cuts,
  and observable continuation ancestry (`2`, refusing `protection_unavailable`),
  same-store temporal ordering requiring `decision_time >= e["at"]` across
  validated cuts (`2b`, refusing `journal_time`), active local preservation holds
  and conservative continuation/sealed-ancestor hold dominance (`3`, refusing
  `protected_use`), unretired referencing records across latest or superseded
  revisions (`4`, refusing `still_referenced`), and policy-bound `{id, version}`
  removal authorization verification when the referenced set is non-empty (`5`,
  refusing `removal_authorization`).
- **Store-wide exclusion fence re-verification.** Requires `removal_eligibility`
  to be evaluated under the store-wide body-removal exclusion fence before
  appending `body_removal_started` and before any `retry_unlink` attempt on an
  open removal.

### `durable-record/v1` designated `body-removal` stream recovery and detached `stream-seal`

- **Successor-stream recovery (`stream_opened.recovery`).** Extends
  [`schemas/durable-record/v1/journal-entry.schema.json`](../../schemas/durable-record/v1/journal-entry.schema.json),
  [`schemas/durable-record/v1/stratum-profile.schema.json`](../../schemas/durable-record/v1/stratum-profile.schema.json),
  and [`docs/standards/durable-record-v1-contract.md`](../standards/durable-record-v1-contract.md)
  with Option B1 designated `body-removal` stream recovery under
  `runtime.incarnation_allocation: "prewrite_durable_ledger"`. Quarantines a
  damaged designated stream without in-place tail rewriting, binds the longest
  valid complete-group prefix (`cut_seq`, `cut_digest`,
  `quarantined_image_digest`) and `runtime.quarantined_designated_streams`
  predecessor chain, and reconciles every `(digest, length)` via the 19-row
  `R1`–`R19` table (`R1 -> R2 -> R3 -> R4..R19`, adding `recovery_incomplete` to
  the closed refusal vocabulary).
- **Sticky post-recovery carry-forward and multi-hop replay.** Preserves
  post-recovery `publishing` (`R7`, `R9`, `R13`, `R19` — transitioning to
  `integrity_loss` if bytes disappear before republication, never reverting to
  `removed` or `unpublished`) and sticky `integrity_loss` (`R6`, `R10`, `R16`,
  `R18` — remaining `integrity_loss` across clean cuts and subsequent recovery
  hops even if un-republished bytes reappear) until cleared by a new
  `body_published(n')` with `n' > floor`. Requires fresh `removal_eligibility`
  and `authorization` before re-issuing an abandoned `R12`/`R13` removal.
- **Detached canonical stream seals (`stream-seal`).** Adds
  [`schemas/durable-record/v1/stream-seal.schema.json`](../../schemas/durable-record/v1/stream-seal.schema.json)
  and
  [`schemas/durable-record/v1/examples/stream-seal.example.json`](../../schemas/durable-record/v1/examples/stream-seal.example.json)
  for detached RFC 8785 JCS stream seals binding `store`, `capability`,
  `stream`, `cut_seq`, `cut_digest`, `effective_restriction_manifest_digest`
  (closed `{holds, retired, inherited}` preimage), sorted/unique transitive
  `ancestor_seals`, `trust_profile: {id, version}`, canonical `sealed_at`,
  `provenance`, and `authorization`. Enforces authenticated closer and permanent
  write fencing across the exact transitive upstream boundary closure, zero raw
  trailing bytes, exact fenced cut length, and conservative sealed-ancestor hold
  checks in `removal_eligibility`.
- **Logical conformance vectors and mutation controls.** Expands
  `scripts/validate-durable-record-fixtures.py` and
  `scripts/test-durable-record-v1-controls.py` by 183 conformance vectors, 17
  schema reject fixtures, and 107 AST mutation witnesses (to 395 vectors, 66
  schema reject fixtures, and 187 AST mutation witnesses).

### `identity-evidence/v0` `native-process-observation:v0` provider profile (draft)

- **Standalone native process observation.** Adds
  [`schemas/identity-evidence/v0/profiles/native-process-observation/`](../../schemas/identity-evidence/v0/profiles/native-process-observation/)
  (`profile.json`, `evidence.schema.json`, `README.md`, and platform examples)
  plus
  [`schemas/identity-evidence/v0/examples/native-process-observation.json`](../../schemas/identity-evidence/v0/examples/native-process-observation.json)
  for observing live OS process incarnation and context facts without requiring
  launch or handle possession evidence (`status: draft`).
- **Visibility vocabulary, namespace descriptors, and Linux `/proc` classes.**
  Defines the seven-state fact visibility vocabulary (`observed`, `not-present`,
  `inaccessible`, `unsupported`, `not-probed`, `error`, `unknown`) mapped 1:1 to
  report capability status, host-scope and clock/user/PID-namespace descriptor
  semantics, three-class Linux `/proc` `openat2` and magic-link resolution rules
  (keeping `magic-link-leaf-not-mount-confined` disclosed), `u32`/`u64` integer
  bounds, pre/post incarnation bracketing, and fail-closed projection into
  `local-process-session:v0`, covered in
  `scripts/test-identity-evidence-controls.py`.

### RFC 8785 canonicalization and RFC 3339 instant helper hardening

- **`scripts/rfc8785-canonicalize.py` and `scripts/test-rfc8785-controls.py`.**
  Replaces recursive JSON parsing and JCS serialization with an iterative
  implementation enforcing explicit input bounds (`--max-bytes`, `--max-depth`,
  `--max-object-members`, `--max-string-bytes`), rejecting all 66 RFC 7493 §2.1
  Unicode noncharacters (`U+FDD0..U+FDEF` and `U+..FFFE` / `U+..FFFF` across
  planes `0..16`, raw or `\uXXXX` escaped), surrogate code points, duplicate
  object keys, and out-of-domain integer tokens before arbitrary-precision
  expansion, and adding `--check`, `--digest`, `--vector`, `--ndjson-array`
  (`--head N`), and `--sort-set` CLI modes.
- **`scripts/rfc3339-instant.py`.** Adds `max_fraction_digits` and
  `reject_submicrosecond_nonzero` options on `parse_rfc3339` and exact
  arbitrary-precision fractional-second ordering in `compare`.

## What a release carries

A crucible release is a GPG-signed annotated Git tag. It publishes no assets,
so there are no `SHA256SUMS` or `SHA512SUMS` files to verify. See
[`docs/security/README.md`](../security/README.md).

## Upgrade notes

- **For `durable-record/v1` adopters:** Stores reclaiming body bytes referenced
  by retired records must evaluate `removal_eligibility` under the store-wide
  exclusion fence and verify policy-bound `{id, version}` removal authorizations
  alongside conservative continuation/sealed-ancestor holds. Stores enabling
  designated `body-removal` stream recovery must declare
  `runtime.incarnation_allocation: "prewrite_durable_ledger"` and keep
  `runtime.quarantined_designated_streams` equal to the successor
  `stream_opened.recovery.previous_stream` chain.
- **For `identity-evidence/v0` adopters:** `native-process-observation:v0` ships
  at `status: draft`; projection into `local-process-session:v0` fails closed
  with typed refusals when required session incarnation or scope facts are not
  `observed`.
- **For downstream repositories vendoring helper scripts:** Re-pin
  `scripts/rfc8785-canonicalize.py` and `scripts/rfc3339-instant.py` to `v0.2.9`
  to pick up iterative JCS bounds, RFC 7493 noncharacter rejection, and
  sub-microsecond instant controls.
