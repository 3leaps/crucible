# Release v0.2.5

**Role prompts add execution continuity; contract controls fix UTF-8 subprocess decoding and large integer body lengths.**

This is a patch release. It adds no contract family and changes no schema or
contract specification. It updates three canonical role prompts with
execution-continuity guidance and fixes two control-script defects in
subprocess output decoding and integer body-length validation.

## Highlights

### Role prompt execution continuity

- **Shared continuity guidance.** `devlead` (`1.2.0`), `devrev` (`1.3.0`) and
  `uxdev` (`1.2.0`) add a shared `Execution continuity` block in `context` and
  two `mindset.principles` entries: carry out the next authorized, in-scope
  action after each result; treat progress reports as intermediate updates
  rather than handoffs; name the blocking dependency, missing authority,
  unavailable capability or unresolved decision before yielding with unfinished
  work; continue independent in-scope work when a blocker affects only part of
  the task; investigate failed checks rather than treating them automatically
  as blockers; preserve verified state and the next authorized action across
  handoffs and resumes; and stop when the assigned outcome completes.
- **Role-specific loops.** `devlead` carries implementation through required
  checks, correction of discovered issues and authorized review handoffs
  without bypassing independent review. `devrev` carries review through
  inspection, proportionate checks, an explicit disposition and re-disposition
  on revised packets without taking over implementation. `uxdev` carries
  interface work through implementation, observation and explicit reporting of
  unavailable devices or assistive technology as verification gaps.
- **Unchanged boundaries.** Existing `authority` and `does_not` blocks,
  `schemas/agentic/v0/role-prompt.schema.json` and the remaining role prompts
  are unchanged.

### Control script fixes

- **UTF-8 subprocess output decoding.** Text-mode `subprocess.run` and
  `subprocess.check_output` calls across the contract and permission control
  scripts specify `encoding="utf-8"` and `errors="replace"` instead of the host
  locale's default encoding. Diagnostics containing non-ASCII or malformed
  bytes no longer fail under a `cp1252` default on Windows; exit-code checks
  retain their behavior, and `scripts/test-portability.py` exercises stdout and
  stderr capture on zero and nonzero exits under a `cp1252` fallback.
- **Large integer body lengths in durable-record/v1 controls.** `integral()` in
  `scripts/test-durable-record-v1-controls.py` checks exact `int` values
  (`value >= 0`) before `math.isfinite`, avoiding `OverflowError` for integers
  above the floating-point range while continuing to exclude booleans, integer
  subclasses, negative integers, fractional floats, non-finite floats, null and
  text. Durable-record/v1 schemas, vectors and contract rules are unchanged.

## What a release carries

A crucible release is a GPG-signed annotated Git tag. It publishes no assets,
so there are no `SHA256SUMS` or `SHA512SUMS` files to verify. See
[`docs/security/README.md`](../security/README.md).

## Upgrade notes

- **For repositories vendoring role prompts:**
  `config/agentic/roles/devlead.yaml` (`1.2.0`),
  `config/agentic/roles/devrev.yaml` (`1.3.0`) and
  `config/agentic/roles/uxdev.yaml` (`1.2.0`) carry updated `context` and
  `mindset.principles` entries. Re-vendor at this tag if adopting execution
  continuity.
- **For repositories pinning contract controls:** re-pinning picks up
  locale-independent UTF-8 subprocess capture across the Python control scripts
  and large-integer `length` handling in
  `scripts/test-durable-record-v1-controls.py`.
- Schemas, contract specifications and release toolchain pins are unchanged.
