# Release v0.1.33

**Experimental durable queue and durable record contracts, verified release
keys, and faster contract checks.**

## Highlights

### Durable queue

The proposed, experimental `durable-queue/v0` family defines an at-least-once
queue as a logical contract, independent of storage engine. It covers a message
envelope, queue-scoped fenced leases, a closed ledger vocabulary with atomic
groups and fold rules, a capability profile that separates build and runtime
facts and states a guaranteed failure model, and a control exchange with typed
per-operation requests and results. Golden examples, one-field schema reject
pairs, semantic reject vectors and core, fan-out and canonicalization behavioral
vectors accompany the standard and ADR-0012. The service-job standard gains a
note distinguishing queue and job idempotency scopes, and transport events from
job completion.

Portable restore, `replay`, cross-queue fan-out and tolerant conformance are
deferred.

### Durable record

The proposed, experimental `durable-record/v0` family defines engine-neutral
record storage: revisioned records with stable identity and RFC 8785 digest
pins, digest-bound body references, provenance, and required retention and
sensitivity classification. An append-only journal shares the durable-queue
consistent-cut rule and carries the records it accepts, so a complete journal
is the portable form of a stream. Keyed idempotent writes return typed
receipts, and a writer without a receipt reconciles by key. A stratum profile
declares the failure model and, per surface, which deletion operation the store
supports. ADR-0013 records the boundary.

v0 journals are append-only. Redaction of journal history, shared stream
metadata, multi-host ownership, merge, a wire binding and behavioral vectors are
deferred.

### Decisions and review

- EPR-0005 (proposed): relied-upon tests take expected results from a source
  the implementation does not determine, and draw specimens from a separate
  authority where a shared corpus exists.
- EPR-0002 states its reference-implementation evidence boundary separately for
  each obligation. The principle and obligations are unchanged.
- The fierce-collaboration standard moves to 0.7.0 with an evidence-residual
  taxonomy: every evidence gap that cannot be resolved before the gate is a
  pre-land blocker, a narrowed claim, a post-merge follow-up, or
  unsupported/fail-closed. A post-merge follow-up covers only evidence the
  present claim does not need. A one-page review card accompanies it.

### Release verification

Signed version tags are verified against release-key anchors shared with the
other 3leaps repositories: a public key containing the primary and one signing
subkey, a fingerprint file for the GPG primary and the minisign key, the
minisign public key, and the required tagger identity.
`scripts/verify-pinned-tag.sh` reads them from the tagged commit, not the
working tree, and requires exactly one good, unexpired signature by the pinned
signing subkey. The release workflow and `make release-verify-tag` use it.
`make release-push-tag` verifies, pushes and confirms the signed tag.

### CI and toolchain

Check runs full repository quality in the pinned Linux tools runner, and
contract checks on GitHub-hosted Windows amd64. The release workflow no longer
re-runs Check. Goneat is pinned to v0.6.3 and the glibc tools runner to v0.5.9,
consumed by immutable digest. Goneat v0.6.3 compiles embedded schemas on first
use rather than at every process start, which shortens each of the many
validator invocations the contract controls make.

## Compatibility

The durable-queue and durable-record bundles are proposed and experimental.
This release does not promote them to stable or certify an adopter. No existing
producer or consumer must change. Other schema-family versions are unchanged.
