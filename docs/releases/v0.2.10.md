# Release v0.2.10

**Date:** 2026-11-11

**Adds a pinned physical Parquet fixture corpus for `durable-index/v0`, completes the independent logical reader, and tightens durable-record framing and schema validation controls.**

This release binds physical fixtures to fixed logical rows, extends independent
logical scenario coverage, and updates the repository's schema-validation
toolchain. `durable-index/v0` remains experimental; these fixtures and controls
do not by themselves qualify a physical reader, writer, or storage runtime.

## Highlights

### Durable-index physical fixtures and logical reader

- Adds 26 Parquet fixtures and six NDJSON twins under the
  [Parquet inventory fixture corpus](../../schemas/durable-index/v0/fixtures/parquet-inventory/README.md).
  The corpus covers ZSTD and UNCOMPRESSED codecs, data-page versions 1 and 2,
  both signed and absent `size_bytes` annotations, multiple row groups, and
  an ordered two-member split of the fixed logical oracle. Twenty negative
  fixtures carry named refusals.
- The [baseline physical fixture controls](../../scripts/test-durable-index-physical-controls.py)
  verify the inventory, exact byte lengths and SHA-256 pins, raw logical-row
  schema checks, logical row semantics, and member-set parity. Parquet decoding
  is separate, bounded evidence; the baseline does not decode the members.
- Extends the independent [TypeScript logical reader](../../scripts/durable-index-reader.ts)
  across all authored logical scenario categories, including byte-bound
  bindings, complete projection graphs, cutovers, cross-member rows, and strict
  parsing, with mutation and inventory controls. Structural schema validation
  remains in the Python/goneat gate.
- Clarifies in the [durable-index contract](../standards/durable-index-contract.md)
  that discovery compilers resolving path segments or partitions to an exact
  finite union of literal prefixes emit canonical `unicode-prefix/v0` plans.

### Durable-record and schema validation

- Rejects blank and whitespace-only durable-record NDJSON journal lines at
  ingest, including writer-abort and reopen paths. Adds ancestor-seal refusal
  controls for unauthenticated closers and non-current live ancestor journals.
- Constrains timestamp seconds in the `durable-record/v0` and `v1` schemas so
  `:60` remains a schema-stage refusal across validator profiles, while the
  semantic timestamp checks remain in place. The
  [v0](../standards/durable-record-contract.md#timestamp-validation-profile-v0)
  and [v1](../standards/durable-record-v1-contract.md#production-time-instants-and-ordering)
  contracts describe the supported timestamp and validator profiles.
- Updates schema controls for exact JSON-number decoding, format validation,
  Unicode and parser refusals, and validator report metadata. Pins Goneat
  `v0.6.8` and the `v0.5.15` glibc runner for repository checks.

## Upgrade notes

- Consumers of the durable-index corpus can verify the new fixed members and
  logical twins with the repository controls. Physical decoding and complete
  graph evidence remain separate requirements for R2/W1/W2/W3 qualification.
- Durable-record consumers should retain ingest framing and semantic timestamp
  checks when updating schemas or validator versions. Existing `v0` validation
  remains supported for historical streams.

## What a release carries

A Crucible release is a GPG-signed annotated Git tag. It publishes no assets,
so there are no `SHA256SUMS` or `SHA512SUMS` files to verify. See
[release security](../security/README.md).
