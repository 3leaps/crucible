# Release v0.1.27

**A curated agentic role catalog with explicit lifecycle semantics, so adopters
can select a coherent public role set and migrate away from retired roles.**

## Overview

v0.1.27 curates Crucible's public agentic role catalog. Twenty role definitions
now have a consistent lifecycle model: core roles form the baseline, supplemental
roles are adopted when needed, and deprecated roles provide a named successor.
The catalog documentation distinguishes approved definitions from drafts and
keeps the schema registry and human-readable documentation in their appropriate
publication domains.

This is a documentation, configuration, and schema-validation release. It adds
no runtime service or consumer-linked code. It also aligns the repository's
strict assessment controls with the files and canonical-byte fixtures they
validate.

## Highlights

### Tiered role catalog

All role prompts declare one of three tiers: `core`, `supplemental`, or
`deprecated`. The catalog adds analyst, delegate, project manager, security
operations, strategist, UX development, and watcher definitions. The active-role
index records which catalog entries are approved and which remain drafts.

Three retired roles remain available as migration adapters: `qa` names `devrev`
and `devlead`; `deliverylead` names `projectmgr`; and `cicd` names `releng` and
`devlead`. They do not carry a separate operational authority or output contract.

### Lifecycle validation that proves its failure cases

The role-prompt v0 schema now requires a tier and recognizes lifecycle status,
authority, outputs, and replacement fields. A deprecated role must have a
deprecated tier and name at least one successor; active roles cannot name a
replacement. New reject fixtures cover missing tiers, empty authority, invalid
or active replacements, lifecycle mismatches, and a deprecated role without a
replacement.

The role-prompt control battery is integrated with configuration linting, so
`make check` exercises both the accepted catalog and each rejection case.

### Documentation and decision records

PDR-0007 is accepted as the catalog curation record. ADR-0007 defines separate
origins for documentation and schema registries, and EPR-0004 records the rule
that publication surfaces preserve their domains of concern. The catalog README,
adoption guide, repository identity guidance, and role documentation consistently
point adopters to the canonical role source and lifecycle information.

### Assessment-control alignment

Strict assessment now applies shell linting only to shell files. The declared
checkmake limit accommodates the comprehensive configuration-lint target. RFC
8785 canonical JSON byte vectors are excluded from text formatting because a
trailing newline would change their canonical bytes; the service-job control
battery continues to verify those bytes and their digests directly.

## Compatibility

Existing role-prompt YAML must add a valid `tier` to validate against the v0
schema. A deprecated role must declare a non-empty `replaced_by` list of valid
role slugs, and non-deprecated roles must not declare one.

Role prompts remain v0 artifacts. Pin the repository revision when a consuming
repository needs a stable catalog snapshot.
