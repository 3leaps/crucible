# Release v0.2.2

**Repository classes are drafted, and durable-record/v1 is amended before
adoption.**

This release adds a repository-classes standard, amends the experimental
durable-record/v1 contract in place, accepts PDR-0008 on the evidence of
v0.2.1, and hardens the release tooling. The durable-record/v1 amendment is
not additive: it changes the digest and pin of every v1 record. It was made on
2026-10-25, when durable-record/v1 had no adopters. The v0 family is
unchanged.

## Highlights

### Repository classes (draft) and ADR-0018

`docs/standards/repository-classes.md` picks a repository's class by its
primary caller: prims, bolts, wits and voys, with pressers as an adjacent
class. It lists per-class MUST characteristics with observable checks, a repo
declaration and a new-repo template. Prims declare a four-language commitment
in one of two profiles (a Rust core, or pure-Go and Rust twins that lock step
once both operate) and may depend on sibling prims under four rules. The class
check is a manual review step until the declaration schema ships. ADR-0018
records the decision.

### Durable-record/v1 amended before adoption

- **Record envelope `v: 1`.** A v1 journal carries `v: 1` records: the v0
  envelope with `v` set to 1 and an optional `produced_at` claim (`instant`,
  `source` of `producer_clock` or `trusted_time`, and evidence when trusted)
  inside the record digest. A `v: 0` record in a v1 journal is refused as
  `record_version`. Content re-recorded into v1 always gets a new digest and
  pin.
- **One instant spelling.** Every v1 wire instant is a valid UTC date and time
  with exactly six fractional digits and no leap second. Readers refuse
  anything else as `instant_spelling` and never normalize under a digest.
- **Keyed retirement.** `retired` gains an optional idempotency key with an
  accepted `retired` write receipt bound to a digest of
  `{stream, record_id, reason, idempotency_key}`. An unkeyed retirement keeps
  no receipt and no replay promise.
- **Ordering.** `seq` orders one stream's journal and is not portable; ordering
  records from several streams by `produced_at` is a presentation order.
- **Stratum profiles.** `runtime.commit_strategy` is one of
  `fsync_file_and_dir`, `fsync_file`, `backend_acknowledged` or `none`, with
  free text in the optional `commit_note`. Both remain information only.
- **Label selection** is an exact, adopter-defined string match, not a store
  guarantee.

All v1 vectors and examples are re-derived for the new envelope. New vectors,
schema rejects and mutation witnesses cover each rule. ADR-0019 and the v1
standard record the amendment.

### Release tooling

- **PDR-0008 is accepted**, citing v0.2.1 as the first tag made under the
  adopted ceremony.
- **The default GPG keyring is never used.** `release-tag` requires
  `THREELEAPS_CRUCIBLE_GPG_HOMEDIR`, a dedicated keyring, and tag verification
  uses the committed pin in a throwaway keyring.
- **Failed GitHub reads are reported as such.** The tag-ruleset guard no longer
  reports an authentication failure as "found 0" rulesets, and
  `release-push-tag` separates a pushed tag from an unreadable verified flag.
- The `release-tag-push` alias is removed.

### Fixed

The durable-queue reference model keeps a fractional `clock_start` when
formatting timestamps.

## What a release carries

A crucible release is a GPG-signed annotated Git tag. It publishes no assets,
so there are no `SHA256SUMS` or `SHA512SUMS` files to verify. See
[`docs/security/README.md`](../security/README.md).

## Upgrade notes

- **For durable-record/v1 implementers:** records are `v: 1`, and every
  digest and pin computed under the previous v1 text changes. Emit canonical
  instants; a reader refuses others. A `v: 0` record is valid only in a v0
  journal.
- **For durable-record/v1 stratum profiles:** replace a free-text
  `commit_strategy` with one of the four values and move the text to
  `commit_note`.
- **For anyone running the release scripts:** set
  `THREELEAPS_CRUCIBLE_GPG_HOMEDIR` for `release-tag`, and use
  `release-push-tag` in place of the removed `release-tag-push`. See
  [`RELEASE_CHECKLIST.md`](../../RELEASE_CHECKLIST.md).
- durable-record v0 and every other contract family are unchanged.
