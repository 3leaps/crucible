# Release v0.2.13

**Date:** 2026-11-22

**Adds the proposed, experimental `durable-runner/v0` contract for portable task execution with journaled recovery, and a proposed process decision for publishing qualification claims from presser evidence.**

## Highlights

- The [durable runner standard](../standards/durable-runner-contract.md) and
  [ADR-0021](../decisions/ADR-0021-durable-runner-contract.md) define task
  identity and idempotency, closed task and attempt transitions, cancellation,
  retry and backoff bounds, deadlines and horizons, single-authority recovery
  with authority generations, and independent durability properties.
- Four modes are specified: `basic`, `retrying`, `journaled` and `scheduled`
  (supplied schedule slots, occurrence sets, coverage evaluation and bounded
  catch-up). The `sealed` mode is reserved and refused.
- The [schema bundle](../../schemas/durable-runner/v0/README.md) carries six
  JSON Schema 2020-12 schemas, examples, one-difference schema reject pairs,
  semantic rejects and 413 behavioral vectors, with an inventory. An adopter
  writes their own harness that drives a runner through the vector operations.
  The pinned surface is the six schemas and `contract.json`; the vector
  documents and operation arguments are not pinned and can change within `v0`,
  so a conformance claim names the release and its `INVENTORY.json`.
- Controls cover the schemas and the behavior: a reference model with named
  guards, mutation controls that require each guard to be caught by a checker
  verdict, refusal-isolation controls, type fuzzing, wire-record validation
  and independent identity and backoff calculations. The model verifies that a
  supplied backoff draw lies inside the permitted band; it does not draw the
  backoff.
- [PDR-0012](../decisions/PDR-0012-publishing-qualification-claims-from-presser-evidence.md)
  proposes a reporting practice for published presser results: identify what
  ran, establish expectations and scope, report each conclusion with its
  evidence, and make the claim verifiable. Fuzz reporting guidance is
  provisional. It adds no schema, registry or runner.
- Contract scripts that loaded the canonicalizer with the removed
  `SourceFileLoader.load_module()` now use `importlib.util`, so the checks run
  on Python 3.15.

## Adoption notes

The standard, ADR-0021 and PDR-0012 are proposed and the contract is experimental. Pin an
exact release or commit when adopting it.

The reference model is a fixture checker, not an implementation oracle. Its
time-zone table covers only `America/New_York` for 2026, it does not model the
recurrence expander or attempt-timeout and deadline expiry while an attempt is
running, and admission is a standalone counter not bound to a task. Instants
beyond the exact-integer microsecond range are not bounded at parse time. A few
normative rules, named in the standard's assurance boundary, have no vectors.
Schema validity and vector agreement qualify no runtime, storage, cloud,
crash-recovery or language implementation; adopters verify those themselves.

## What a release carries

A Crucible release is a GPG-signed annotated Git tag. It publishes no assets,
so there are no `SHA256SUMS` or `SHA512SUMS` files to verify. See
[release security](../security/README.md).
