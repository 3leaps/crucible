# Release v0.1.34

**Draft agent interface classifiers and profiles, and faster offline contract
checks.**

## Highlights

### Agent interface classifiers

Four draft categorical dimensions describe separate aspects of one declared
agent interaction:

- `agent-seat-class`: who manages the addressed session's lifecycle (`live`,
  `headless`, `hosted` or `unknown`). It is classified as a relationship, not a
  product name.
- `agent-control-surface`: the entrypoint selected for the interaction, such as
  an interactive UI, a bounded invocation, a session API or an embedded API.
- `agent-transport`: the carrier at one connection boundary. Each hop is
  classified separately; protocols, framing and delivery patterns are not
  transport values.
- `agent-adapter-confidence`: an evidence-derived assessment for one adapter,
  build, operation and scope. Its states are categorical. Policies list the
  states they accept rather than apply a threshold. A read timeout alone is
  not proof that the remote operation did not execute, though a missed
  deadline can still demonstrate failure of a required timely-response
  behavior.

A value-only schema validates a nonempty selection of these dimensions.
Consumers may adopt a subset; an adopted but unclassified dimension uses
explicit `unknown`. Classifier values describe interfaces; they do not grant
control, consent or authority.

### Agent interface profiles

A companion draft profile schema describes a possible agent interface in more
detail than the classifiers:

- an endpoint role graph with per-hop protocol stacks, including separate
  request and observation bindings, pinned to exact operations, protocols and
  messages;
- execution lifetime, context persistence, resume and reconnect as distinct
  properties, where resume requires durable context;
- delivery receipt, execution start and completion, and cursor-commit signals
  as distinct mappings with their own correlation scopes.

Synthetic examples and a local checker accompany the standard. The checker
validates the schema and local references only. A profile is a declaration,
not a grant, a delivery receipt or a qualification; pin resolution, wire
qualification and runtime authority remain the consumer's responsibility.

### CI and toolchain

Windows contract checks run as three parallel shards, and a guard fails if a
contract check runs in no shard or in more than one. Schema validation uses
goneat's embedded meta-schemas by default, so checks make no network fetches.
Goneat is pinned to v0.6.4 and the glibc tools runner to v0.5.10, consumed by
immutable digest, and Check fails if the runner's goneat differs from the pin.
Goneat v0.6.4 no longer probes package managers on every command, which
shortens each of the many validator invocations the contract controls make.

## Compatibility

The agent interface classifiers and profiles are drafts. They add new
dimensions and schemas and do not change existing classifier schemas,
inference identity records or agent-wait semantics. No existing producer or
consumer must change. Other schema-family versions are unchanged.
