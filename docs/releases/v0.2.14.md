# Release v0.2.14

**Date:** 2026-11-23

**Adds the proposed, experimental `record-collection/v0` contract family, files proposed PDR-0011 and PDR-0013, refines proposed PDR-0010, adds a non-normative timestamp source-precision adopter guide, and strengthens the release checklist and version-surface guards.**

## Highlights

- **Proposed `record-collection/v0` contract family**
  ([`schemas/record-collection/v0/`](../../schemas/record-collection/v0/README.md)):
  a sibling family (with zero changes to `schemas/durable-record/v1/` or
  `schemas/project-work/v0/`) defining `set` (canonical ascending pin order,
  no repeats) and `list` (stored array order, optional `allow_repeats`)
  collections of exact `durable-record/v1` revision pins, `member_count`,
  bounded `members` (`maxItems: 10000`), `append_only` extension rules,
  `closure_claim` (`none | complete_at_write`), and body-backed evidence
  verification. Includes entry and payload schemas, 6 examples, 14
  one-leaf-diff schema reject pairs, 27 behavioral vectors, 7 semantic rejects,
  and offline controls.
- **[PDR-0011](../decisions/PDR-0011-verified-package-registry-publication.md)
  (proposed)**: authorizes package registry publication against the verified
  final archive, separates verification from credentialed publication, clarifies
  adoption-candidate status, and requires separately reviewed bindings for OIDC
  trusted-publisher mechanisms.
- **[PDR-0010](../decisions/PDR-0010-verified-immutable-release-publication.md)
  (proposed, refined)**: adds the PDR-0011 cross-link, concrete companion-tag
  effective-ruleset evaluation, and explicit obligations for external
  verification records, draft resume without clobbering, release-notes and
  intent-flag binding, stable asset identity, lock scope, closed fixed-set
  declarations, and tag-only verification.
- **[PDR-0013](../decisions/PDR-0013-byte-exact-repository-data.md)
  (proposed)**: specifies declaring byte-exact repository paths in root
  `.gitattributes` (`-text -filter -ident -working-tree-encoding`) and verifying
  effective attributes and checked-out bytes with Git (`git check-attr`,
  `git ls-files --eol`, `git hash-object --no-filters` against `HEAD`), with a
  POSIX `sh` reference check and EPR-0002 negative controls. Updates
  [`docs/operations/ci-baseline.md`](../operations/ci-baseline.md) and
  [`docs/knowledge/cicd/github-actions/windows-runners.md`](../knowledge/cicd/github-actions/windows-runners.md)
  to replace the `core.autocrlf=false` recommendation for adopting repositories.
- **Non-normative timestamp source-precision adopter guide**
  ([`docs/guides/durable-record-timestamp-source-precision.md`](../guides/durable-record-timestamp-source-precision.md)):
  gives adopter-owned versioned payload recipes for seconds/milliseconds
  zero-padding and nanosecond floor truncation with discarded remainders,
  leaving `durable-record/v1` schemas and standards unchanged.
- **Release tooling and checklist alignment** (`RELEASE_CHECKLIST.md`,
  `Makefile`, `scripts/release-guard-release-surfaces.sh`): guards
  `package.json` and the README header version badge, preflights `jq` before
  mutating `VERSION`, aligns rollback and tag verification with the explicit
  repository URL, and adds `release.yml` run/job confirmation and
  no-run/failed-run/draft triage guidance.

## Adoption notes

- `record-collection/v0` is proposed and experimental; pin an exact release or
  commit when adopting it. Schema validity and vector agreement qualify no
  runtime or storage implementation.
- PDR-0010, PDR-0011, and PDR-0013 remain **proposed**. Crucible itself stays
  on [PDR-0004](../decisions/PDR-0004-release-publication-gate.md) for release
  publication and is **not yet covered** by PDR-0013; each adoption is a
  separate reviewed change.
- The timestamp source-precision guide is non-normative and makes no change to
  `durable-record/v1`.

## What a release carries

A Crucible release is a GPG-signed annotated Git tag. It publishes no assets,
so there are no `SHA256SUMS` or `SHA512SUMS` files to verify. See
[release security](../security/README.md).
