# Release v0.1.28

**A bounded, cooperative presentation-priority hint for portable agent-wait
registrations, with canonical-digest semantics preserved.**

## Overview

v0.1.28 extends `agent-wait/v0` registrations with an optional integer
`priority` from `0` through `255`. The field is a cooperative presentation
hint: higher values express greater presentation urgency. It does not add
scheduling, authorization, quota, or abort authority, and it does not relax or
override the contract's frozen wait rules.

This is an additive v0 contract update. Existing registrations without
`priority` remain valid and preserve their existing serialized form.

## Highlights

### Cooperative registration priority

The registration object accepts `priority` as an optional integer with a closed
range of `0..=255`. Documented reference values are background (`0`), normal
(`50`), and urgent (`100`), while implementations may use any integer in the
valid range.

Consumers read an omitted value as `50` for presentation. They must not insert
that value before RFC 8785 canonicalization. Priority remains subordinate to
required registration behavior, coverage and fairness rules, aggregate bounds,
deadlines, lease and authentication requirements, and acknowledgment and
retention behavior.

### Canonical-digest integrity

The release adds registration-set goldens at priorities `0`, `50`, `100`, and
`255`. The agent-wait control battery recomputes each recorded RFC 8785 digest.
It also proves that a registration with omitted priority and one with explicit
`50` match after only `priority` is removed, while their canonical payloads and
recorded digests remain distinct.

### Failure evidence

Schema reject/baseline pairs cover four invalid values: `-1`, `256`, `50.5`,
and `"urgent"`. The control battery validates accepted baselines, rejects the
invalid fixtures, and checks that each reject differs from its baseline in one
field.

## Compatibility

`priority` is optional, so existing `agent-wait/v0` registrations remain valid.
Consumers that do not use presentation priority can preserve the field as part
of the canonical registration payload. Consumers that use it interpret omitted
priority as `50` only after digest-sensitive processing.

The contract remains `agent-wait/v0`; consumers needing a stable revision
should pin the repository revision they adopt.
