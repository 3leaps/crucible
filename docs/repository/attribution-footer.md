# Attribution Footer

**Canonical URL** (hosted site planned — v0.1.x):
`https://crucible.3leaps.dev/repository/attribution-footer`

Check and append the attribution trailer that every 3leaps commit message and
PR body must end with. This is the enforcement companion to
[commit-style.md](commit-style.md).

## Required footer

Every commit message **and** every PR body ends with exactly these three
trailer lines, after one blank line:

```
Role: devlead
Co-authored-by: <Model Name> <noreply@3leaps.net>
Committer-of-Record: @3leapsdave
```

- **Role** is the bare role slug (`devlead`, `devrev`, `cxotech`, …). Never
  `agent-*`, and never a team-prefixed name like `bravo-devlead`; team names
  are internal and leak on public repos.
- **Co-authored-by** is the model you are actually running (e.g. `Grok 4.7`,
  `Claude Opus 4.6`, `GPT-5.6`), at `noreply@` one of `3leaps.net`,
  `3leaps.dev`, `fulmenhq.dev`, `lanytehq.dev`. Match the org when you can.
- **Committer-of-Record** is always `@3leapsdave`.

The PR body needs the footer too: most repos squash-merge with the PR body as
the commit message. GitHub carries only `Co-authored-by` from branch commits
into a squash, so a footer that exists only on branch commits is lost.

A `Generated by …` line may appear in the body. It is optional prose, not one
of the three required trailers.

## What the check enforces

The last three non-empty lines, in this order, are `Role`, `Co-authored-by`,
and `Committer-of-Record`, preceded by a blank line.

| Rule                     | Result                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| Trailing whitespace/CRLF | Ignored (GitHub UI PR bodies often arrive as CRLF)                                         |
| HTML comments            | Stripped before the scan, so PR-template and review-wrapper comments after the footer pass |
| `agent-*` role           | Fail                                                                                       |
| Team-prefixed role       | Fail (`<nato-team>-<role>`, for example `bravo-devlead`)                                   |
| Unknown catalog slug     | Warning, not failure (`wright`, `docs`, and other seat-local slugs)                        |
| Co-authored-by key case  | Accepted (`Co-Authored-By` is a notice); canonical spelling is `Co-authored-by`            |
| Co-authored-by value     | Non-empty model name and exactly `<noreply@DOMAIN>` with DOMAIN in the four allowed hosts  |
| Committer-of-Record      | Exactly `@3leapsdave`                                                                      |

Trailer keys are matched case-insensitively because git trailers are
case-insensitive.

Two modes:

- **PR body** (default, and the GitHub check): the three trailers must be the
  last three non-empty lines. Extra trailers after `Committer-of-Record` fail.
- **Commit**: extra trailing `Co-authored-by:` lines after the required footer
  are tolerated. GitHub may append those on squash for additional authors.
  Extra `Co-authored-by` lines **between** the three required trailers still
  fail.

The GitHub check validates the PR body always. Checking each PR commit is
opt-in (on by default for `3leaps/crucible` itself).

## Local script

The checker is `scripts/check-attribution.py`. Same implementation for the
Action, the reusable workflow, and the git hook. No network, no third-party
Python packages.

```bash
# Validate a file (commit message or PR body)
python3 scripts/check-attribution.py check path/to/message.txt

# Validate a PR body from GitHub
gh pr view 12 --json body -q .body | python3 scripts/check-attribution.py check -

# Append or repair a footer (idempotent; replaces a partial trailing footer)
python3 scripts/check-attribution.py append \
  --role devlead --model "Grok 4.6" --domain 3leaps.dev \
  path/to/message.txt

# Git commit-msg hook entry. Appends when role/model/domain are set,
# otherwise check-only.
python3 scripts/check-attribution.py commit-msg .git/COMMIT_EDITMSG
```

`append` and `commit-msg` take `--domain` one of `3leaps.net`, `3leaps.dev`,
`fulmenhq.dev`, `lanytehq.dev`. `--committer` is accepted only as
`@3leapsdave`.

Environment variables for the hook (all three required to append):

| Variable                | Purpose                         |
| ----------------------- | ------------------------------- |
| `ATTRIBUTION_ROLE`      | Bare role slug                  |
| `ATTRIBUTION_MODEL`     | Model display name              |
| `ATTRIBUTION_DOMAIN`    | One of the four noreply domains |
| `ATTRIBUTION_COMMITTER` | Must be `@3leapsdave` if set    |
| `ATTRIBUTION_CHECKER`   | Absolute path to this script    |
| `CRUCIBLE_ROOT`         | Clone of `3leaps/crucible`      |

Run `make test` (or `make check`) to execute `scripts/test-check-attribution.sh`.

### Install the commit-msg hook

From a clone of this repository:

```bash
python3 scripts/check-attribution.py install-hook
```

From another repository that has `3leaps/crucible` as a sibling clone at
`../crucible`, run the same command after setting `CRUCIBLE_ROOT`, or copy
the script and point `ATTRIBUTION_CHECKER` at it:

```bash
export CRUCIBLE_ROOT="${CRUCIBLE_ROOT:-$HOME/src/crucible}"
python3 "${CRUCIBLE_ROOT}/scripts/check-attribution.py" install-hook
```

The hook looks for the checker in `ATTRIBUTION_CHECKER`, `CRUCIBLE_ROOT`,
`scripts/check-attribution.py` in the current repo, then
`../crucible/scripts/check-attribution.py`.

Pass `--force` to replace an existing `commit-msg` hook that is not already
this checker.

For agents that should repair missing footers on every commit:

```bash
export ATTRIBUTION_ROLE=devlead
export ATTRIBUTION_MODEL="Grok 4.6"
export ATTRIBUTION_DOMAIN=3leaps.dev
```

Without those variables the hook is check-only and will reject a commit that
lacks the footer.

## GitHub check

A composite action finds this repository's copy of the script via
`github.action_path` (three levels up from
`.github/actions/check-attribution/`). A reusable workflow wraps it so a
caller can `uses:` one file.

Pin by tag or SHA. Do not float on `main` in production.

### Composite action (preferred cross-org pin)

```yaml
name: Attribution footer

on:
  pull_request:
    types: [opened, edited, synchronize, reopened, ready_for_review]

permissions:
  contents: read
  pull-requests: read

jobs:
  attribution:
    runs-on: ubuntu-latest
    steps:
      - uses: 3leaps/crucible/.github/actions/check-attribution@<sha>
        with:
          check-commits: false
```

Replace `<sha>` with a commit SHA of `3leaps/crucible`, or with a version tag
once this ships in a release. The action does not check out the caller
repository. It reads `pull_request.body` from `$GITHUB_EVENT_PATH`.

`check-commits: true` lists PR commits through the GitHub API (requires
`pull-requests: read`) and validates each message in commit mode.

### Reusable workflow

```yaml
name: Attribution footer

on:
  pull_request:
    types: [opened, edited, synchronize, reopened, ready_for_review]

permissions:
  contents: read
  pull-requests: read
  actions: read

jobs:
  attribution:
    uses: 3leaps/crucible/.github/workflows/check-attribution.yml@<sha>
    permissions:
      contents: read
      pull-requests: read
      actions: read
```

The called workflow cannot use `uses: ./.github/actions/check-attribution`
because GitHub resolves local actions against the **caller** repository. It
therefore checkouts `3leaps/crucible` at the SHA of this workflow
(`github.sha` on `3leaps/crucible` PRs, otherwise the `referenced_workflows`
SHA of the reusable-workflow pin) and runs `scripts/check-attribution.py`.
`actions: read` is required on the caller so that lookup can succeed.

If the lookup fails, call the composite action directly and pin it yourself.

This repository enables the workflow on its own pull requests. Commit-message
checking is on for `3leaps/crucible` and off by default for other callers
(`check-commits` input).

## Required checks and org rulesets

This change does not configure org rulesets. To require the check later:

1. Add one of the caller snippets above to the target repository.
2. In a repository or org ruleset, add a **required status check** named after
   the **caller** job. With the snippets above that name is `attribution`.
   For a reusable workflow the check name is the caller job id, not a name
   from `3leaps/crucible`.
3. Wait for the check to report at least once on the default branch (or
   disable "Require check to pass for the latest push") so GitHub will offer
   the name.

**Cross-org limit.** GitHub [required workflows](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets#require-workflows-to-pass-before-merging)
in a ruleset must live in a repository the ruleset's org can select. An org
ruleset for `lanytehq` or `fulmenhq` cannot name
`3leaps/crucible/.github/workflows/check-attribution.yml` as a required
workflow. Put a thin same-org caller workflow in each org (the snippets
above) and require **that** workflow as a status check.

Reusable workflows and composite actions from a **public** repository can
still be _called_ cross-org when the caller workflow pins them. That is the
supported path for `3leaps`, `lanytehq`, and `fulmenhq`.

Fork pull requests: keep `pull_request` (this check) rather than
`pull_request_target`, so untrusted forks cannot run with base-branch
secrets.
